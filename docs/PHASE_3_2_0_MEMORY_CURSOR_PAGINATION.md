# Phase 3.2.0 — Memory cursor pagination

## API contract

Authenticated `GET /api/memories` supports `limit=1..100` (default 20) and an optional opaque `cursor`.

A list response retains the existing fields and adds pagination metadata:

- `memories`: current page records
- `total`: number of records in this page (preserves the existing endpoint meaning)
- `next_cursor`: signed opaque cursor, or `null`
- `has_more`: whether another page exists

The list order remains `updated_at DESC, id ASC`. Continuation uses the matching keyset predicate:
`updated_at < cursor.updated_at OR (updated_at = cursor.updated_at AND id > cursor.id)`.

Cursors are HMAC-SHA256 authenticated with Web Crypto and bind version, position, tenant, principal, project, review filter, issue time and expiry. They are integrity-protected, not encrypted; do not put sensitive data in cursor payloads. They expire after 24 hours. The verifier rejects expired tokens, future issue times, invalid TTLs, malformed/non-canonical Base64URL, incorrect signature length, invalid D1 timestamps, and scope/filter mismatches.

Relevance search (`q`) remains ranked by the existing repository algorithm and does not support cursor pagination. Supplying both `q` and `cursor` is rejected with HTTP 400. Search responses return `next_cursor: null` and `has_more: false`.

The cursor secret must be at least 32 UTF-8 bytes and must never be committed to source control, written to `.dev.vars` in a tracked file, or exposed to the browser.

## Cloudflare secret provisioning

Before enabling cursor pagination in a deployed Pages environment, provision a fresh high-entropy secret through Cloudflare's encrypted secret store. From an authenticated operator shell, run:

```sh
wrangler pages secret put CURSOR_SIGNING_SECRET --project-name aegis-infinity
```

When prompted, supply a value generated by an approved password manager or cryptographically secure generator (at least 32 random bytes). Do not put the value on the command line, in shell history, CI logs, GitHub Actions variables, source files, or commit messages. Provision Preview separately if Preview deployments are used.

This PR does not run that command, change Cloudflare secrets, deploy Pages, or apply any remote D1 migration. The new index migration is included for review and isolated CI/local verification only. Production secret provisioning and migration application require a separately approved rollout.

## Operational notes

- Missing/weak signing secret fails closed: a request requiring cursor verification or issuance receives HTTP 503.
- Invalid, expired, tampered, or out-of-scope cursor receives HTTP 400.
- Existing tenant/principal/project authorization and repository filters remain authoritative; cursor scope is an additional integrity boundary, never an authorization substitute.
- Cursor pages can reflect updates between requests because the established API order is based on mutable `updated_at`. A record updated during traversal may move relative to the cursor. This preserves existing ordering semantics; snapshot pagination would require a separate immutable snapshot/version contract.
