# Hey Jev evaluation and AEGIS-native adaptation

**Status:** Research decision; no third-party code imported, no device capture enabled, no runtime or production configuration changed.
**Reviewed:** 22 November 2026
**Target:** Existing AEGIS repository and companion architecture.

## Executive decision

Hey Jev is a useful engineering reference for voice-first interaction and desktop task execution. AEGIS should **adapt the patterns, not embed or fork Hey Jev**.

The strongest reference for Windows behaviour is [deva-san/hey-jev](https://github.com/deva-san/hey-jev). The original [henryklunaris/hey-jev](https://github.com/henryklunaris/hey-jev) is a Mac-only application. [legionsound/hey-jev](https://github.com/legionsound/hey-jev) explores richer screen control and agent sessions. [King4s/hey-jev](https://github.com/King4s/hey-jev) explores a Rust/provider abstraction rewrite, but its own commit notes say microphone capture, wake word, push-to-talk, dictation and native window were not yet implemented at that checkpoint.

None of these repositories reports a repository-level SPDX licence in GitHub metadata; the original and the examined forks do not expose a top-level licence file. The LegionSound fork explicitly says the original has no licence and that it does not add one. The MIT licence included for its separately adapted `typesafe-computer-use` component applies to that component only. The deva-san fork contains a separate MIT licence for vendored Hermes Agent code, not a licence for the whole Hey Jev repository. **Do not copy, vendor, redistribute or adapt their source code without explicit permission and a clear licence grant.** This report records architectural observations and independently implementable requirements only.

## Findings by project

### 1. Original Henryk project

Repository: https://github.com/henryklunaris/hey-jev

- macOS Sequoia/Tahoe only; AppleScript and macOS Keychain integration are platform-specific.
- Wake phrase or right-Option push-to-talk; local faster-whisper transcription; a single structured decision call; deterministic local app/media actions; spoken replies.
- General questions are delegated to a separate LLM only after the command classifier decides the utterance is a question.
- The README describes optional dictation that sends audio to an external transcription provider. This is a distinct privacy boundary from local command transcription.
- Requires external service credentials for its described decision, speech and answer services.

**AEGIS lesson:** Separate command classification from open-ended reasoning; keep common actions deterministic; make any cloud audio path explicit and opt-in. Do not adopt the Mac-specific runtime.

### 2. LegionSound fork

Repository: https://github.com/legionsound/hey-jev

- Extends the Mac implementation with screen observation, UI interaction and ACP agent sessions.
- Its README describes permission requests being routed to a confirmation UI, with unanswered requests rejected rather than auto-approved.
- Its task flow reads the current UI, plans a bounded step, acts, then checks the result. Stored procedures are generated by code from successful runs rather than accepted directly from model output.
- Its README reports 632 automated tests at the inspected revision; this is a project-reported result, not an independently executed test result.
- The fork's README says the original repository has no licence and the fork does not add one.

**AEGIS lesson:** Use observe → plan → policy-check → act → verify as the device-task lifecycle. Keep approvals explicit and action-scoped. Do not import its code or assume its safety claims replace AEGIS Sentinel.

### 3. deva-san Windows fork

Repository: https://github.com/deva-san/hey-jev

- Windows 10/11 port with a local speech pipeline described as Silero voice activity detection, Smart Turn end-of-utterance detection and Parakeet speech recognition.
- It deliberately waits through short pauses to avoid splitting compound requests and supports interruption/turn cancellation.
- Uses Windows UI Automation first for screen controls, with screenshot/vision fallback for interfaces that cannot be understood structurally.
- Its README describes a constrained action catalogue, read-back and confirmation for consequential actions, secret-field exclusions and post-action verification.
- It describes routines learned from successful, code-verified task executions and reused without a model call.
- Its README claims free-first model selection but also acknowledges free models/services can disappear or change without notice. Its example voice provider's free tier was stated to end in November 2026.
- The repository metadata exposes no repository-level licence. The separate MIT licence under `hermes_memory/LICENSE` covers vendored Hermes Agent material only.

**AEGIS lesson:** This is the richest source of behaviour to study, especially turn detection, interruption, structured UI observation, result verification and deterministic routine replay. Its desktop-native implementation and Windows-only dependencies are not a fit for Cloudflare Pages or mobile browsers. Free-tier availability must never be treated as a permanent contract.

### 4. King4s Rust rewrite

Repository: https://github.com/King4s/hey-jev

- Reworks the assistant around a Rust core and provider traits for intent, language model, speech and transcription.
- Describes configurable provider selection, a macOS driver and a Linux driver.
- At the inspected commit, the project notes explicitly say microphone capture, wake word, push-to-talk, dictation and native window were not yet implemented.
- No repository-level licence is exposed in GitHub metadata.

**AEGIS lesson:** Provider interfaces and platform adapters are good architectural patterns. The incomplete capture path means this is not a ready-made portable voice runtime.

## AEGIS design decision

Keep the existing AEGIS companion, intelligence and Sentinel boundaries. Do not create a second assistant, a second memory system or a second approval authority.

### Target flow

```text
Microphone / typed input
        |
        v
Device or browser audio client
        |
        v
Voice session gateway (authenticated, bounded)
        |
        v
Speech input provider -> transcript + confidence + timing
        |
        v
Turn manager -> interruption / end-of-turn decision
        |
        v
AEGIS intelligence core
        |
        +---- deterministic local/low-cost intent path
        |
        +---- model route through Infinity Zero when reasoning is needed
        |
        v
Sentinel preflight for protected device or external actions
        |
        v
Optional device companion executes a narrow, typed capability
        |
        v
Result verification -> response text -> speech output provider
```

The avatar/companion renderer receives presentation events only. It must not receive credentials, raw tool authority or direct access to private memory.

### Delivery slices

1. **Voice session contract (first):** versioned events for session start/stop, capture state, transcript partial/final, turn complete, assistant speaking, interruption, provider error and disconnect. Validate state transitions, message size, sequence numbers, cancellation and ownership. No microphone or provider integration in this slice.
2. **Browser push-to-talk (second):** explicit user gesture to request microphone permission; visible recording state; stop/mute control; bounded audio frames; authenticated short-lived session; no background listening by default. If browser/device support is unavailable, retain text input.
3. **Provider-neutral speech adapters (third):** local device transcription first where practical; optional cloud speech providers behind explicit configuration and Infinity Zero budget checks. Audio is not sent to a model provider merely because a voice session exists.
4. **Turn-taking and interruption (fourth):** start with deterministic silence/VAD thresholds and user interruption. Add a Smart Turn-like classifier only after measured tests show fewer mid-sentence cut-offs without excessive latency. Pin model assets and verify hashes.
5. **Speech output (fifth):** pluggable TTS with text captions, mute/stop and graceful text fallback. Never depend on a temporary free voice tier for core availability.
6. **Device companion (sixth):** optional signed, authenticated Windows/Linux/macOS helper. It exposes a small allowlisted capability API, not a general shell. Pairing is user-approved; credentials remain in the device OS credential store; every action is evaluated by Sentinel.
7. **Screen perception (seventh):** use structured accessibility/UI metadata first. Screenshot capture is user-initiated, scoped to the selected window, visibly indicated and sent externally only under a separate consent and data policy. Never retain screenshots by default.
8. **Verified routines (eighth):** record only code-observed successful actions; bind routines to device, application, capability versions and owner; revalidate UI state before each action; revoke routines when their dependencies change.

## Non-negotiable safeguards

- No always-on microphone, camera or screen capture by default.
- No raw audio, screenshots, transcripts or secrets in ordinary application logs.
- No arbitrary shell, PowerShell, AppleScript, keyboard macro or unrestricted browser-control capability exposed to the model.
- Passwords, passkeys, OTPs, payment details and security prompts remain user-handled.
- Sending, publishing, purchasing, deleting, granting access, installing, shutting down or changing account/security settings require Sentinel approval bound to the exact action and parameters.
- A model-generated plan is untrusted input. Re-check the current screen and action parameters immediately before execution.
- Stop, disconnect, session expiry, device revocation and Sentinel denial must cancel pending work.
- Unknown provider pricing, model eligibility or quota means no paid fallback.
- Never claim a task succeeded until the device reports and verifies the resulting state.

## Fit against current AEGIS

AEGIS already has a documented companion architecture with separate Intelligence Core, Companion Experience Engine, Voice & Audio Engine, Perception Gateway, Client Shell and Sentinel responsibilities. This evaluation should be implemented within those boundaries. In particular:

- Use the existing companion presence/session contract rather than inventing a second state system.
- Use the existing AG-UI stream for assistant text/events where appropriate; do not overload it with raw audio transport.
- Use the existing capability/grant/approval/audit system for device actions.
- Use the existing Infinity Zero route and quota policy for any metered speech or reasoning provider.
- Keep browser capture and device-local capture as different adapters because browser lifecycle and native device permissions differ.

## Verification required before implementation

- Confirm the exact active companion feature branch and its existing contracts before adding files; avoid duplicating work already present on an open PR.
- Inspect current AEGIS auth/session, AG-UI cancellation, capability grants and Sentinel approval APIs.
- Write contract tests first for session ownership, explicit capture consent, event ordering, cancellation, interruption, quota denial and device revocation.
- Validate on real target browsers/devices. Desktop CPU timing from another project is not evidence of acceptable mobile performance.
- Independently review model and speech-provider terms, free-tier status, retention, region and data handling before enabling any external audio path.
