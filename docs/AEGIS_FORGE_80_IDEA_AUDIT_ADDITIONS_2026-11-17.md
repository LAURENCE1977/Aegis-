# AEGIS Forge — Capability Additions from the 80-Idea Audit

**Research date:** 17 November 2026  
**Disposition:** Four capability additions accepted into the Forge research register, subject to the gates below.  
**Scope:** MediaPipe Face/Hand/Gesture tasks, FastMCP sidecar adapters, and native scam/phishing/document-risk protection.

## Executive decision

The four additions fill useful gaps and do not duplicate the capabilities already recorded in the register (Whisper.cpp STT, HeadTTS, Vindex video summarisation, WeKnora/sqlite-vec knowledge retrieval, Understand-Anything/Tree-sitter code understanding, Sigma/YARA rules and Crawl4AI browsing).

The architecture remains AEGIS-native: Sentinel owns authorisation, identity and audit; Forge owns task execution; Vault owns secrets; local-first modules own privacy-sensitive processing. External feeds, model packages and sidecars are replaceable evidence/adapters, not trusted authorities.

| Addition | Decision | Confidence | Initial implementation class |
|---|---|---:|---|
| MediaPipe Face Landmarker | Accept as an optional local biometric *signal* and camera-interaction primitive; not sufficient alone for secure liveness/authentication. | High on capability; low on anti-spoof assurance | Browser/PWA optional module |
| MediaPipe Hand Landmarker + Gesture Recognizer | Accept for custom gestures and accessibility experiments; do not claim full sign-language translation from 21 landmarks. | High on hand tracking; low on general sign-language coverage | Browser/PWA optional module |
| FastMCP | Accept as an optional Python sidecar adapter framework; AEGIS MCP contracts and Sentinel remain authoritative. | High | Local desktop/Linux sidecar |
| Scam/phishing/document-risk guard | Accept as a native AEGIS capability family. Treat feed licences, false positives and document-analysis limitations explicitly. | High on native parsing/rules; feed-specific | Core contracts + edge/local adapters |

## 1. Camera interaction and anti-spoof signals — MediaPipe Face Landmarker

**Upstream:** https://github.com/google-ai-edge/mediapipe  
**License:** MediaPipe repository declares Apache-2.0. Preserve the licence and NOTICE/attribution obligations for any redistributed component. Model assets and separately downloaded dependencies must be inventoried independently.  
**Relevant API:** `@mediapipe/tasks-vision`, Face Landmarker web task.

### Verified capabilities
- Face Landmarker returns 478 3D facial surface landmarks.
- It can optionally return 52 facial blendshape coefficients and a 4×4 facial transformation matrix.
- Web task supports image and video/live-camera input modes and is demonstrated with WebAssembly.
- The browser sample/runtime can use WASM and CPU/GPU acceleration; actual performance and backend availability vary by device/browser.

### Smallest useful primitive
A local frame-processing adapter that accepts an ephemeral camera frame and emits only a short-lived challenge result, for example:
- face present and suitably positioned;
- instructed head pose reached;
- blink-like eye-closure sequence observed;
- challenge completed within a bounded time window.

The adapter must not emit face embeddings, identity templates, persistent landmark histories or video recordings. Drop frame references and intermediate arrays as soon as processing completes; do not place frames or landmarks in telemetry, logs, D1 or RAG.

### Critical security correction
Face Landmarker is a geometry/expression task, not a certified presentation-attack detector. A blink/head-turn challenge can be replayed or generated by a sufficiently capable synthetic video, and a normal webcam cannot prove camera integrity. Therefore:
- call the result a **liveness signal**, never proof of identity or guaranteed liveness;
- never use it as the sole factor for login, account recovery, payment approval or privilege elevation;
- prefer WebAuthn/passkeys or another phishing-resistant possession authenticator for account authentication;
- if enabled as a supplementary risk signal, bind a fresh unpredictable challenge to the current session, use short expiry and replay protection, and fail closed to a safe alternative rather than locking out users;
- keep camera permission explicit, show an active-camera indicator and offer a non-camera path;
- pin and locally bundle WASM/model assets for offline operation; do not rely on an unpinned CDN at runtime;
- verify model asset licensing, integrity hashes, version provenance and browser/device support separately.

**Disposition:** Research accepted; no biometric authentication claim or production login integration approved.

## 2. Hand gestures and sign-language accessibility — MediaPipe Hand Landmarker / Gesture Recognizer

**Upstream:** https://github.com/google-ai-edge/mediapipe  
**License:** Apache-2.0 at repository level; separately verify model assets and dependencies.  
**Relevant APIs:** Hand Landmarker and Gesture Recognizer in `@mediapipe/tasks-vision`.

### Verified capabilities
- Hand Landmarker tracks 21 3D landmarks per detected hand.
- Gesture Recognizer classifies a supported set of hand gestures and can be extended with custom gesture models.
- The browser tasks are available through the MediaPipe web vision APIs.

### Smallest useful primitive
A local gesture-event adapter:
- consumes frames only while the user explicitly enables camera interaction;
- converts landmark sequences into a small, user-configurable gesture vocabulary;
- emits a semantic event such as `companion.dismiss`, `navigation.next` or `duress.request`;
- discards frames and landmark sequences after recognition;
- requires confirmation for consequential actions.

### Sign-language boundary
Twenty-one hand landmarks are not a sign-language translator. Full sign languages use hand shape, motion, orientation, body posture, facial grammar, context and language-specific syntax. A fingerspelling model needs appropriate labelled training/evaluation data and may not generalise across sign languages, dialects, users or camera conditions. Start with user-configurable gestures and a separately scoped fingerspelling research track; do not market generic gesture recognition as sign-language understanding.

### Duress and accessibility boundary
- A gesture can request a duress workflow, but camera-based gesture detection must never be the only emergency path.
- False triggers, motor differences, injury, tremor, lighting, camera placement and privacy constraints must be considered.
- Provide accessible alternatives (visible button, keyboard shortcut, voice phrase where safe, hardware shortcut where supported).
- Do not silently contact emergency services, disclose location or send messages. Any escalation path requires explicit user configuration, clear confirmation policy and a reliable cancellation mechanism.
- Do not record video or store a gesture biometric profile.

**Disposition:** Accept as optional local accessibility/interaction primitive; full sign-language translation is a separate future capability requiring expert and Deaf-community co-design.

## 3. Lightweight Python MCP sidecars — FastMCP

**Upstream:** https://github.com/jlowin/fastmcp  
**Package:** https://pypi.org/project/fastmcp/  
**Verified package metadata:** FastMCP 4.1.8 published 10 November 2026; Apache-2.0; Python >=3.10. Verify the exact repository tag and licence at the time a dependency is pinned.

### Smallest useful primitive
Use FastMCP decorators and typed tool/resource definitions to expose a local Python capability as an MCP server, particularly for existing local tools such as Vindex or Crawl4AI. AEGIS should wrap each sidecar in a versioned capability manifest and a narrow adapter contract.

### Transport and trust model
- Prefer stdio for a child process launched and supervised by the local AEGIS node.
- If Streamable HTTP is required, bind to loopback by default; remote binding requires authenticated transport, explicit network policy and a Sentinel grant.
- Do not assume that a FastMCP HTTP endpoint is equivalent to AEGIS's existing `POST /mcp` bridge. Implement and test a protocol adapter rather than silently changing the public bridge contract.
- Validate tool names, JSON schemas, payload size, timeouts, output size and resource access at the AEGIS boundary.
- Sidecars cannot read Vault secrets directly, choose their own permissions, call other tools freely or write AEGIS canonical state.
- Treat tool descriptions, prompts, resource content and outputs as untrusted data; they cannot override system policy.
- Pin versions/hashes, inventory transitive dependencies and record sidecar provenance. No automatic package installation or arbitrary Python execution.

**Disposition:** Accept as an optional interoperability adapter, not as the AEGIS orchestrator or policy engine. LangGraph remains excluded as a duplicate of the native D1 orchestrator.

## 4. Scam, phishing, malicious-link and document-risk protection

This is an AEGIS-native capability family. It should combine deterministic parsing, local threat intelligence, explainable risk signals and a read-only document clause review skill.

### 4A. URLhaus and OpenPhish feeds

**URLhaus:** https://urlhaus.abuse.ch/  
- URLhaus shares URLs associated with malware distribution and provides a community API.
- Its API requires an Auth-Key for downloads and documents fair-use principles. The official API page says companies, networks or individuals with commercial/for-profit needs may require the enhanced commercial service.
- Some published URLhaus rulesets are labelled CC0-1.0 by downstream ruleset indexes; do not generalise that label into a blanket claim that every API response, dataset, payload or service interaction is unrestricted. Track data licence, API terms and authentication/fair-use obligations as separate fields.
- Never visit, resolve, preview, crawl or download a malicious destination as part of feed ingestion or URL checking. Fetch only the provider's documented feed/API endpoint.

**OpenPhish:** https://openphish.com/phishing_feeds.html  
- The Community Feed is limited and refreshed every 12 hours.
- Its terms restrict free community-feed use to personal, academic or independent research that does not support business operations; it is not an assumed free production dependency for AEGIS.
- Commercial use requires written permission or a paid product. Do not redistribute the feed or derived portions without permission.
- Keep OpenPhish disabled in production unless AEGIS has documented permission and a compatible licence/terms review.

### 4B. Domain and URL analysis

**Mozilla Public Suffix List:** https://github.com/publicsuffix/list  
- Repository declares MPL-2.0; use the official PSL source and preserve applicable notices.
- The PSL identifies public suffix boundaries (for example, `co.uk`) and helps calculate registrable domains. It is not a threat-intelligence list and does not detect phishing by itself.

Native URL guard pipeline:
1. Parse with a standards-compliant URL parser; reject malformed or ambiguous encodings.
2. Canonicalise scheme/host safely; normalise IDNs using a documented IDNA/UTS #46 policy and retain the original display form.
3. Calculate registrable domain using a pinned PSL snapshot.
4. Flag deceptive signals: punycode/Unicode confusables, mixed scripts, homoglyphs, excessive subdomain depth, lookalike brand tokens, suspicious user-info, unexpected ports, IP-literal hosts, URL shorteners and misleading path/query text.
5. Compare the canonical host/URL against locally cached, licence-compatible threat indicators with source, timestamp, expiry and confidence.
6. Return an explainable risk assessment with reasons and evidence age. Absence from a feed is **not** proof of safety.
7. Never automatically navigate to or fetch the submitted destination. Any optional reputation enrichment must use an explicitly approved, privacy-reviewed service and must not leak the user's full URL/query to a third party.

### 4C. Edge deployment and cache design
- Cloudflare Workers can perform bounded URL parsing and lookup; Workers KV can cache provider data, and Cron Triggers can periodically refresh feeds.
- Cloudflare documents free-tier KV limits and Worker CPU/time limits. Do not describe the design as unlimited or guarantee that every parsing/enrichment workload fits the free tier.
- Separate feed ingestion from user requests. Validate feed format, bound response bytes/entries, pin provider endpoints, use ETags/checksums where available, record fetched-at/expiry, and fail safely when stale.
- Store only threat indicators and minimal metadata in KV; never store user-submitted full URLs, browsing history or document contents as analytics.
- Keep a local/offline parser and local allow/deny lists so core checks still work without Cloudflare or a provider feed.

### 4D. Read-only contract and terms clause audit
An AEGIS-native skill can identify and explain clauses such as:
- automatic renewal, cancellation barriers and unilateral price changes;
- broad data collection/sharing, retention and secondary use;
- liability exclusions, indemnities and asymmetric remedies;
- arbitration, governing law, jurisdiction and dispute restrictions;
- hidden fees, penalties, variable rates and payment authorisations;
- perpetual licences, assignment and rights to user content;
- unilateral amendment, termination and suspension rights.

Required behaviour:
- quote the exact source passage and identify its document/page/section;
- explain why it may matter in plain language, distinguish fact from interpretation, and list questions to ask before signing;
- identify missing context, jurisdiction and document date; do not invent a clause or legal consequence;
- label output as informational issue-spotting, not legal advice or a definitive enforceability opinion;
- do not sign, accept, submit, negotiate or modify legal terms on the user's behalf;
- process locally where feasible and never send contracts to third-party models without explicit consent.

## Cross-cutting privacy and security rules

- No camera frames, biometric templates, raw landmarks, user URLs or contract text in routine logs or product analytics.
- Explicit camera permission, visible indicator, immediate stop control and non-camera alternatives.
- No facial identity recognition, emotion inference, crowd surveillance or person tracking.
- No camera gesture as sole authentication or emergency channel.
- No malicious destination fetch, DNS resolution, browser preview or automatic navigation during reputation checks.
- Feed entries are untrusted indicators with source/age/confidence; never treat a clean result as a safety guarantee.
- Sidecar tool descriptions and outputs are untrusted; Sentinel independently authorises every operation.
- No automatic install, remote execution, unbounded egress or new production secrets.

## Suggested delivery sequence

1. **Contracts and threat model:** typed URL assessment, feed provenance, camera ephemeral-signal, gesture-event and document-clause finding schemas.
2. **Pure local URL guard:** parsing, IDN display/canonicalisation, PSL registrable-domain extraction, confusable heuristics and explainable deterministic tests.
3. **Document clause audit:** read-only ingestion, citation/section anchors, uncertainty and jurisdiction prompts; no signing or external upload.
4. **Gesture accessibility prototype:** opt-in local MediaPipe hand tracking and configurable non-consequential gestures.
5. **Face challenge research:** test replay, screen re-recording, virtual camera and synthetic-video attacks before considering any security use; retain passkeys as primary authentication.
6. **FastMCP adapter:** one harmless read-only local sidecar, stdio transport, strict schema, process supervision, timeouts, audit and Sentinel mediation.
7. **Feed integration:** only after provider terms are cleared for the intended use, with bounded scheduled ingestion and freshness metadata.

## Acceptance tests and open gates

- URL parser: malformed URLs, credentials/user-info, Unicode and punycode, mixed-script labels, trailing dots, unusual ports, IP literals, nested encoding, shorteners and PSL wildcard/exception rules.
- Reputation: stale/missing feed, provider outage, malformed feed, false positive, duplicate entries, expiry and no outbound request to listed URLs.
- Clause audit: exact quotes and anchors, hallucination rejection, ambiguous jurisdiction, missing text and conflicting clauses.
- MediaPipe: offline asset loading, camera permission denial, no-camera fallback, low-light/low-end devices, dropped frames, stop-camera cleanup and proof that no frame/landmark leaves the client.
- Gesture: left/right hand variation, orientation, accessibility alternatives, false positives, cancellation and no silent escalation.
- Liveness: printed photo, static screen, replayed video, recorded challenge, virtual camera and generated video; any untested attack means no high-assurance claim.
- FastMCP: tool spoofing, oversized input/output, malformed schemas, timeout, process crash, malicious tool descriptions, loopback binding and denial of ungranted tools.

## Verification and implementation status

This is a researched architecture addition, not a claim that the features are implemented. No MediaPipe package/model, FastMCP dependency, feed, sidecar or browser camera workflow has been installed or enabled by this research. Production integration is blocked on the explicit gates above.
