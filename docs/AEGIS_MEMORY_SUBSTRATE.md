# AEGIS Native Memory Substrate v0.3

## Purpose

AEGIS owns its memory model, provenance, policy, storage and retrieval. Kytheros Strata informs memory/retrieval design; Niko1221 Strata is a separate optional local-inference provider; Meet Nod informs the future computer-use worker. None is a runtime dependency.

## Implemented on `feature/native-memory-substrate`

- Typed, bounded, attributed memory records with confidence, sensitivity, lifecycle and expiry.
- Cloudflare D1 repository with exact owner and personal/project scope filtering.
- Authenticated endpoints:
  - `GET /api/memories` — list accepted memories; `?review=1` also includes candidates.
  - `POST /api/memories` — create a candidate for owner review.
  - `GET /api/memories/:id` — owner-scoped record.
  - `PATCH /api/memories/:id` — accept, supersede or retract.
  - `GET /api/memories/:id/events` — immutable lifecycle history.
  - `GET /api/memories/export` — authenticated JSON export of all owner memories and lifecycle history; `?projectId=` exports personal scope and `?projectId=<id>` exports one active Project Space.
- Candidate memories are excluded from normal retrieval. Only accepted, unexpired, non-restricted records are eligible for chat recall.
- Bounded lexical retrieval supports partial-term matches and exact owner/project scope.
- Chat `POST /api/ag-ui` retrieves up to eight approved personal memories by default. When the owner explicitly selects a Project Space, it retrieves up to four relevant personal and four relevant project memories, after verifying the project is active and owner-scoped. The maximum JSON context block is 6,000 characters. Provenance accompanies each record; the system prompt explicitly treats memory as untrusted reference data, never instructions.
- If D1 is missing or memory retrieval fails, chat fails open to the existing behaviour without memory context; it does not widen scope or invent memories.
- Mobile-first Memory panel in `index.html`: add candidate memories to personal or selected Project Space scope, approve/reject, correct accepted memories through candidate replacements, view immutable history, and export owner data as JSON. It renders memory text using `textContent`, not HTML.
- Project Space selector is shared with chat: the owner explicitly chooses personal-only or one active Project Space. The memory panel can be scoped separately to the same active project.
- Append-only lifecycle audit is generated by D1 triggers on create and status change. Database triggers reject UPDATE/DELETE on the audit table.
- Project-scoped records have a database foreign key to the owner-matched Project Space.

## Canonical shared D1 migrations

Apply **one ordered directory** to the shared Project Spaces + Memory database:

1. `migrations/shared/0001_project_spaces.sql`
2. `migrations/shared/0002_memories.sql`
3. `migrations/shared/0003_memory_lifecycle_audit.sql`
4. `migrations/shared/0004_memory_corrections.sql`

This avoids running multiple nested directories that reuse migration numbers. The original `migrations/workspaces` and `migrations/memory` files are feature-source copies; do not independently apply them to the same D1 database in addition to `migrations/shared`.

The runtime job database is a separate service/database and keeps its own migration directory.

## Security model and limitations

- The current application is single-owner. The API derives the canonical owner ID server-side after validating the signed AEGIS session; owner IDs are never accepted from request bodies.
- Project scope is checked against an active Project Space and enforced again by the D1 foreign key.
- Reads require the existing signed session; writes require same-origin validation.
- Restricted memories are deliberately excluded from chat retrieval. Sensitivity is still metadata, not a general multi-user access-control system.
- Memory content is untrusted data, never an instruction or permission. Retrieved text cannot grant tools or bypass Sentinel.
- Memory history stores IDs, scope, lifecycle states and timestamps, not the memory content.
- Owner export includes all lifecycle states (including retracted, superseded, expired and restricted records), provenance and audit events. It is bounded to 500 memory records and 2,000 lifecycle events per export; the response indicates if it was truncated. Exports are `no-store` attachments.
- No automatic model extraction is enabled. New records enter the candidate queue and require owner acceptance.
- Search is lexical, not vector/embedding-based. This avoids paid APIs and GPU dependencies.
- The legacy `/api/memory` KV notes endpoint remains separate for backward compatibility.

## Research inputs and AEGIS decisions

### Kytheros Strata — persistent memory

https://github.com/kytheros/strata

Reported Apache-2.0 project using SQLite/FTS5 and Cloudflare Workers/D1 patterns, hybrid retrieval, provenance and quality gates. High-value design reference. A caller-supplied identity header is not authentication; any multi-tenant HTTP deployment requires a verified authentication boundary. AEGIS rebuilds selected patterns natively and keeps its own session, owner/project policy and audit authoritative.

### Niko1221 Strata — local inference

https://github.com/Niko1221/Strata

Separate project from Kytheros Strata. Reported MIT local inference/API server. Hardware and desktop assumptions make it unsuitable as a required Chromebook/iPhone/iPad dependency. Optional future provider adapter only; no code import, model download or hardware purchase.

### Meet Nod — computer use

https://github.com/n8n-io/nod  
https://blog.n8n.io/meet-nod/  
https://nod.n8n.io/docs/

Reported Apache-2.0 personal computer-use agent with desktop-hosted browser/workspace, approval gates, credential handling, memory and schedules. Architecture reference only. AEGIS should build an isolated, provider-neutral worker behind Sentinel, explicit per-action approval, a secret vault, redacted audit, cost limits and durable server-side jobs. Never expose unrestricted browser, shell or filesystem access to an agent.

## Explicit non-goals

- No direct runtime dependency on either Strata project or Nod.
- No automatic acceptance of model-generated memories.
- No vector database/GPU requirement for the first release.
- No arbitrary shell, filesystem or browser execution from the control plane.
