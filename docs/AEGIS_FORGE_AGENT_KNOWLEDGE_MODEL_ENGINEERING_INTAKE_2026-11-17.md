## Architecture decisions

### 1. AEGIS remains the control plane
Prime Agent, Agno, smolagents, SuperAGI and other frameworks may contribute patterns or isolated workers. None becomes the source of truth for identity, memory, task state, approvals, policy, autonomy or audit. The native AEGIS orchestrator and Sentinel remain authoritative.

### 2. One knowledge architecture, pluggable storage
Use the existing Guardian catalogue, provenance-aware knowledge and local SQLite/FTS foundations first. Code-Graph-RAG can inform symbol/call/data-flow graph enrichment. Chroma is a local vector benchmark; Weaviate is a possible scale-out service. Do not create three competing knowledge stores or duplicate indexing pipelines.

### 3. Model routing without vendor capture
LiteLLM may be evaluated as a replaceable protocol gateway. AEGIS owns routing policy, privacy, provider consent, budgets and fallback. Local inference must work without LiteLLM, hosted gateways or paid providers.

### 4. Eval-driven learning, not uncontrolled self-modification
DSPy, Guidance, Braintrust-style evaluation and Prime Agent's continual harness inform a native Eval Forge. Store versioned datasets, prompt/program versions, score definitions, held-out results, failure cases, reviewer identity and rollback pointers. Promotion from experiment to production is a gated proposal, never silent self-change.

### 5. Fine-tuning is a later research phase
Unsloth, Axolotl, LLaMA-Factory, TRL and torchtune are complementary but overlapping training toolchains. Select one workflow only after model, dataset, hardware and objective are defined. Model licences do not inherit repository licences; user content is not training data without explicit opt-in.

### 6. Inference serving is capability-tiered
BentoML is a lighter serving candidate; Ray Serve and Triton suit more complex distributed/GPU workloads. TGI and LoRAX are archived and should not be selected as new default serving foundations. Start with existing local runtimes and measure before adding a serving cluster.

### 7. Security tooling is authorised and isolated
sqlmap is not a general-purpose crawler or production feature. Any future integration requires explicit target ownership/authorisation, bounded test plan, isolated disposable worker, no destructive/exfiltration tests, audit and human approval. Its GPL terms and alternative proprietary embedding licence need legal review.

## Delivery priority

- **P0 — Native architecture:** add capability contracts and a comparative scorecard; keep AEGIS control plane, current Guardian D1/SQLite persistence and existing orchestration.
- **P1 — Code intelligence:** evaluate graph schema/impact analysis from Code-Graph-RAG against existing Tree-sitter/code-memory capabilities; read-only prototype only after a measured gap.
- **P2 — Evaluation forge:** native versioned eval datasets, deterministic scorer interfaces, held-out regressions and evidence-backed promotion. DSPy/Guidance patterns are candidates.
- **P3 — Model protocol:** provider-neutral inference contract and optional LiteLLM compatibility adapter; no required gateway.
- **P4 — Retrieval benchmark:** compare existing SQLite/FTS against Chroma; consider Weaviate only for demonstrated scale requirements.
- **P5 — Speech/model lab:** defer Unsloth/Axolotl/LLaMA-Factory/TRL/torchtune until a defined model, consented dataset and feasible compute budget exist.
- **P6 — Serving scale:** benchmark BentoML only if local runtimes are insufficient; Ray/Triton require measured multi-GPU or multi-node need.
- **P7 — Experimental infrastructure:** celld fault-injection/backup/restore evaluation in a disposable test environment only.
