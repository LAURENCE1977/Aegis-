AEGIS is an evolving, modular AI workspace designed to bring conversation, durable project context and carefully governed tools into one mobile-first experience.

Explore the source ↗ How it is designed

A working project, not a finished product. Capabilities are labelled by their actual implementation status.

01 / DESIGN PRINCIPLES

One core. Replaceable parts.

AEGIS is being built around a portable core and clear boundaries, so providers and clients can evolve without locking the project to one vendor or device.

01

Provider-neutral

Model and infrastructure providers should sit behind replaceable adapters. A provider change should not require rebuilding the whole workspace.

02

Workspace-led

Projects, files and durable context are the working foundation. Conversation is an interface to the workspace, not the only place work exists.

03

Human-governed

Tools follow least-privilege rules. Sensitive or consequential actions require explicit approval, traceable decisions and a way to revoke access.

04

Portable by design

The first client is the responsive web experience, with progressive enhancement for phones, tablets and desktop browsers.

02 / REPOSITORY-RECORDED FOUNDATION

What exists today.

The project README and technical notes describe the following source-level foundations. Hosting and production status must be verified separately.

SOURCE IMPLEMENTED

Mobile-first web interface

A browser-based interface designed for phone, tablet and Chromebook layouts.

SOURCE IMPLEMENTED

Authenticated application APIs

Cloudflare Pages Functions with signed, expiring browser sessions and protected endpoints.

INITIAL READ-ONLY SLICE

AEGIS Bridge

A limited MCP endpoint exposing status and descriptive registries. It is not a general-purpose connector or execution service.

SOURCE FOUNDATION

Forge and capability policy

Read-only public repository discovery and descriptive capability declarations, with no automatic permission grants.

NOT YET DEPLOYED

Durable runtime worker

A bounded job-processing foundation exists in source. Live infrastructure provisioning and deployment are separate steps.

03 / DIRECTION

Build carefully. Expand deliberately.

The roadmap is an ambition, not a claim that every capability is already available.

  1. 01

    Reliable web and PWA experience

    Responsive layouts, accessibility, resilient sessions and a consistent experience across supported browsers.

  2. 02

    Durable workspace and runtime

    Persistent project context, resumable jobs, observable status and safe recovery.

  3. 03

    Governed integrations

    Explicit identity, narrow scopes, human approvals, audit trails and revocation before wider tool access.

  4. 04

    Specialist agents and provider choice

    Composable agents and model adapters with measurable quality, cost and reliability.
